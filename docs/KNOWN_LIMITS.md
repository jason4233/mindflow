# 已知設計限制

以下限制已在 `CODEX_ARROWS_REBUTTAL.md` 的主 session 裁決中採認，本輪維持現狀。

## 2.2 方向候選採 90° 圓錐加權

- 行為：候選必須位於方向軸左右各 45° 內，並以「軸向距離 + 偏軸距離 × 2」排序；結果不保證是 Euclidean distance 最近的節點。
- 觸發條件：懸浮節點、manual offset、混合局部 structure，或節點被刻意拉散，使候選明顯偏離方向軸時。

## 2.3 完全重疊或完全同分沒有視覺語意 tie-break

- 行為：中心完全重疊的節點無法由方向鍵互相選取；同方向候選若中心與分數完全相同，結果取決於 `positions` 的 `Map` 插入順序。
- 觸發條件：兩個以上節點中心完全重疊，或多個候選具有完全相同的中心與計分結果時。

## 2.4 極端節點尺寸只以中心點判斷

- 行為：方向導覽只比較 node box 中心，不比較外框最近邊，因此結果不一定是肉眼所見的最近節點。
- 觸發條件：候選節點的寬度或高度差異極大，使邊界距離與中心距離的排序不一致時。

## 2.5 佈局切換動畫期間使用終點座標

- 行為：layout change 後 `positions` 立即更新為終點，但 DOM 約有 300ms transition；動畫途中方向導覽依終點而非螢幕當下位置計算。
- 觸發條件：切換佈局後約 300ms 內按方向鍵，且節點仍在移動時。

## 桌面殼：關窗備份 8 秒上限

關窗時的最終備份最多等 renderer 8 秒；若 renderer 完全卡死，將記錄錯誤後照常關窗，最後數秒的修改可能遺失（常規流程已實測無虞）。來源：DESKTOP2 自首 #6。
